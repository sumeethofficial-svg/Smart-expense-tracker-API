# Smart Expense Tracker API

A small REST API for tracking personal expenses, built with **FastAPI** and
a JSON-file storage backend (no database required).

## Features

- `POST /expenses` — add an expense (`title`, `amount`, `category`, `date`)
- `GET /expenses` — list all expenses, optionally filtered with `?category=`
- `GET /expenses/total` — overall total, plus a breakdown by category
  (add `?category=` to scope the `total` field to one category)
- `DELETE /expenses/{id}` — delete an expense by id

Interactive API docs are auto-generated by FastAPI at `/docs` once the
server is running.

## Requirements

- Python 3.10+

## Install

```bash
pip install -r requirements.txt
```

(If you prefer a virtual environment: `python -m venv .venv && source .venv/bin/Activate.ps1` before the `pip install`.)

## Run the server

```bash
uvicorn src.main:app --reload
```

## The API is then available at (MOST IMP PART)

```bash
`http://127.0.0.1:8000`
(docs at`http://127.0.0.1:8000/docs`), add /docs after getting the primary url 
```

Data is persisted to `expenses.json` in the working directory by default.
To use a different file (e.g. to keep a scratch file out of the repo),
set `EXPENSES_DATA_FILE`:

```bash
EXPENSES_DATA_FILE=/tmp/expenses.json uvicorn src.main:app --reload
```

## Run the tests

```bash
pytest tests/ -v
```

Each test runs against its own temporary JSON file (via a pytest fixture
in `tests/conftest.py`), so the test suite never touches your real
`expenses.json` and tests don't interfere with each other.

## Example usage

```bash
# Add an expense
curl -X POST http://127.0.0.1:8000/expenses \
  -H "Content-Type: application/json" \
  -d '{"title": "Coffee", "amount": 4.5, "category": "Food", "date": "2026-07-31"}'

# List all expenses
curl http://127.0.0.1:8000/expenses

# Filter by category
curl "http://127.0.0.1:8000/expenses?category=Food"

# Totals (overall + by category)
curl http://127.0.0.1:8000/expenses/total

# Delete an expense
curl -X DELETE http://127.0.0.1:8000/expenses/1
```

## Design notes

- **Storage**: `src/storage.py` keeps an in-memory list as the working
  copy and rewrites the whole JSON file on every mutation. That's the
  simplest correct approach for a single-user, low-volume personal
  tracker; it would need to change (e.g. append-only log, real DB) if
  this ever had to handle concurrent writers or large datasets.
- **Validation**: Pydantic enforces `amount > 0`, non-blank `title`/
  `category`, and a real `date` value at the API boundary, so bad input
  is rejected with a `422` before it ever reaches storage.
- **Test isolation**: the FastAPI app builds its `ExpenseStore` at
  import time, pointed at `EXPENSES_DATA_FILE`. The test fixture sets
  that env var to a fresh `tmp_path` file and re-imports the app for
  every test, so tests can't leak state into each other or into your
  real data file.
